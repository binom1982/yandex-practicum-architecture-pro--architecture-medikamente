# Улучшения

## Механизм тегирования данных (Data Tagging)

Для реализации принципа *Privacy by Design* и автоматизации защитных мер необходимо внедрить сквозное тегирование данных. Тег должен путешествовать вместе с данными от момента создания до удаления.

**1. Схема тегирования (Метаданные):**
Предлагается использовать составной тег в формате: `[ДОМЕН]_[УРОВЕНЬ_КРИТИЧНОСТИ]_[ЖИЗНЕННЫЙ_ЦИКЛ]`

* **Примеры тегов:**
  * `MEDICAL_CRITICAL_REST` (Медицинская тайна, критическая, хранится)
  * `PII_HIGH_TRANSIT` (ПДн, высокая чувствительность, передаётся)
  * `FINANCE_MEDIUM_REST` (Финансы, средняя чувствительность, хранится)

**2. Инструменты и уровни применения тегов:**

| **Уровень системы**            | **Инструмент / Механизм тегирования**                                                                                              | **Как работает**                                                                                                                                                                                                                                                                   |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Уровень Базы Данных (To-Be)       | Column-level tagging в PostgreSQL (через `COMMENT ON COLUMN `или расширения вроде `pg_tag`) + Row-Level Security (RLS).                   | СУБД «знает», что столбец `diagnosis` имеет тег `MEDICAL_CRITICAL`, и применяет к нему шифрование или маскирование при запросах.                                                                                |
| Уровень Приложения / API          | Кастомные HTTP-заголовки (например,`X-Data-Classification: PII-HIGH`) и аннотации в коде (Java/Spring `@SensitiveData`). | API-шлюз или микросервис читает заголовок и автоматически применяет политики: логирование без данных, шифрование ответа.                                                                        |
| Уровень Файлов / DLP                  | Системы DLP (Data Loss Prevention, например, InfoWatch или Solar Dozor) + метаданные Office/NTFS ADS.                                     | При попытке отправить файл с тегом `MEDICAL_CRITICAL` по почте или на USB DLP-система блокирует действие и генерирует алерт.                                                                                     |
| Уровень Озёра Данных (Data Lake) | Apache Atlas или аналогичный Data Catalog.                                                                                                              | Автоматическое сканирование загружаемых файлов, присвоение тегов на основе регулярных выражений (например, поиск паттернов СНИЛС или медицинских диагнозов). |

## Карта мер защиты по доменам данных

На основе выявленных проблем и тегов определяем конкретные криптографические и организационные меры для каждого домена.

| **Домен данных** | **Примеры данных**                                      | **Требуемые меры защиты (To-Be)**                                                                                                                                                                                                                                                                                                       |
| --------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Медицинская тайна | Диагнозы, результаты анализов, медкарты  | Шифрование at rest (TDE на уровне СУБД или прозрачное шифрование файлов),<br />Обфускация/Маскирование при отображении для персонала без прямых полномочий,<br />Строгий аудит (кто открыл, когда, зачем). |
| ПДн пациентов         | ФИО, телефон, email, адрес                                  | Псевдонимизация (замена прямых идентификаторов на искусственные ключи) для аналитики,<br />Шифрование in transit (TLS 1.3) для всех каналов передачи, <br />RBAC на уровне строк (RLS).                                                   |
| Финансовые данные | Суммы оплат, чеки, данные ККМ                       | Контроль целостности (хеширование записей),<br />Шифрование канала (замена OLE на защищённый REST/gRPC с mTLS), <br />отказ от двойного учёта в Excel.                                                                                                              |
| Кадровые данные     | Зарплаты, паспортные данные сотрудников | Разделение доступа (только HR и главбух),<br />Шифрование резервных копий, <br />маскирование в интерфейсах 1С для неавторизованных ролей.                                                                                                               |


## Диаграммы потоков данных (To-Be)

Основные бизнес-процессы:

1. Регистрация пациента и запись на приём ([диаграмма](diagrams\БП-1_регистрация_пациента_и_запись_на_приём_(tobe).puml))
   *Описывает первичный сбор персональных данных (ПДн) и их сохранение в незащищённые файловые хранилища.*
2. Оказание медицинских услуг и учёт анализов ([диаграмма](diagrams\БП-2_оказание_медицинских_услуг_и_учёт_анализов_(tobe).puml))
   *Описывает работу с врачебной тайной и специальными категориями ПДн (состояние здоровья, результаты анализов).*
3. Обработка платежей и финансовый учёт ([диаграмма](diagrams\БП-3_обработка_платежей_и_финансовый_учёт_(tobe).puml))
   *Описывает движение финансовых данных, включая проблемный "двойной учёт" кассиров.*
