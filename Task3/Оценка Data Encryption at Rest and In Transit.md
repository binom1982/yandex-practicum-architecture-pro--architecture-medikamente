# Оценка Data Encryption at Rest and In Transit

## Классификация данных, обоснование необходимости защиты выделенных классов и инструменты защиты данных

| **Данные**                                                                                                                                                                                                                                                                                 | **В чём необходимость защиты**                                                                                                                                                                                                                                                                                                 | **Инструменты защиты**                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Специальные категории ПДн и медицинские данные** <br />``ФИО, диагнозы, результаты анализов, медицинские заключения.``<br />**Критическая чувствительность**       | **Требования:** 152-ФЗ (ст. 10 — специальные категории ПДн), приказы ФСТЭК России.<br />**Риски:** Штрафы Роскомнадзора, репутационные потери, шантаж пациентов, судебные иски.                                   | **At Rest:**• TDE или pgcrypto для PostgreSQL.<br />• BitLocker для файлового сервера (Windows Server).<br />• СКЗИ (КриптоПро) для соответствия высоким уровням защищенности 152-ФЗ.<br />**In Transit:**• TLS 1.2/1.3 для API (мобильное приложение, интеграция с лабораторией).<br />• mTLS для трафика между микросервисами в Kubernetes. |
| **Платежные и финансовые данные** <br />``Реквизиты банковских карт, история транзакций, данные о зарплатах.``<br />**Высокая чувствительность**                                  | **Требования:** PCI DSS (если принимаются карты), банковская тайна, защита коммерческой тайны. <br />**Риски:** Финансовое мошенничество, штрафы от платежных систем, уголовная ответственность. | **At Rest:**• Токенизация (хранение токенов вместо реальных данных карт).<br />• Шифрование файловых баз 1С или переход на СУБД с шифрованием.<br />**In Transit:** <br />• TLS 1.3 с строгими cipher suites для обмена с банками и ФНС.<br />• VPN/IPsec для выделенных каналов связи.                                                        |
| **Учетные данные и средства аутентификации** <br />``Логины, хэши паролей, токены сессий, SSL-сертификаты, ключи шифрования.``<br />**Критическая чувствительность** | **Требования:** Защита средств аутентификации, криптографическая защита по стандартам ФСТЭК. <br />**Риски:** Полный захват контроля над системами, компрометация всех данных компании.        | **At Rest:**• Хеширование паролей (Argon2, bcrypt) с уникальной "солью".<br />• HashiCorp Vault для хранения мастер-ключей, сертификатов и токенов API.<br />**In Transit**:<br />• Передача JWT только по HTTPS с флагами Secure и HttpOnly.<br />• Строгая валидация сертификатов.                                                                                    |
| **Данные ТМЦ и операционные данные** <br />``Остатки на складе, закупочные цены, внутренние регламенты.``<br />**Средняя чувствительность**                                            | **Требования:** Защита коммерческой тайны, внутреннее пользование. <br />**Риски:** Промышленный шпионаж, нарушение непрерывности бизнеса, утечка конкурентной информации.                               | **At Rest:**<br />• Разграничение прав NTFS + аудит доступа.<br />**In Transit:** <br />• gRPC over TLS или HTTPS для внутренних коммуникаций (замена небезопасного OLE в 1С).                                                                                                                                                                                                                                                |
