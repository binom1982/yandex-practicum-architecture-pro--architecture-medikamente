# Анализ ситуации и определение ключевых компонентов, затрагиваемых миграцией

**1. Текущее состояние (As-Is):**

* **Архитектура:** Монолитная, с общими ресурсами, развернутая на одном физическом сервере (Windows Server 2022).
* **Хранение данных:** Файловый режим «1С:Бухгалтерия» и «1С:Торговля и склад», локальные Excel-файлы, JPG, PDF на общем диске. Отсутствие аудита действий и контроля доступа (кроме доменной аутентификации).
* **Интеграции:** Устаревшие технологии (OLE для связи ККМ с 1С по TCP/IP).
* **Процессы:** Высокая доля ручного труда, двойной учет, отсутствие автоматизированных пайплайнов и мониторинга.

**2. Цели миграции (To-Be):**

* Поддержка 5-кратного роста объема данных и команды (масштабируемость).
* Усиление безопасности конфиденциальных данных (PII) в соответствии с законодательством РФ.
* Переход на единую систему (порталы для клиентов и ресепшена, платежный шлюз, CRM).
* Интеграция с лабораторией анализов через защищенные API-контракты.
* Создание озера данных для BI, ML и AI.

**3. Ключевые компоненты, затрагиваемые миграцией:**

1. **Базы данных и хранилища:** Переход от файловых систем к масштабируемым реляционным СУБД (Postgres), аналитическим хранилищам (ClickHouse) и озеру данных.
2. **Серверное оборудование и инфраструктура:** Переход от единой точки отказа (один физический сервер) к отказоустойчивому кластеру (Kubernetes).
3. **Коммуникационные каналы:** Замена синхронных блокирующих вызовов (OLE) на современные асинхронные и защищенные API (REST/gRPC с шифрованием).
4. **Бизнес-логика:** Декомпозиция монолита на независимые микросервисы с четкими границами доменов.

## Отчёт по оценке узких мест при миграции ИС компании

### Введение

Целью данного отчёта является анализ потенциальных узких мест и рисков при миграции информационной системы компании «Медикаменте» из текущего состояния (As-Is: монолит, файловые базы, ручные процессы) в целевое состояние (To-Be: микросервисная архитектура, Kubernetes, защищённое хранение PII, озеро данных).

### Диаграмма Исикавы (Fishbone Diagram)

Для систематизации рисков использован метод диаграммы Исикавы.

Основные категории узких мест: Инфраструктура, Программное обеспечение, Данные, Персонал, Процессы.

### Выявленные проблемные зоны

1. **Юридические и репутационные риски:** Текущее хранение PII в Excel и общих папках без аудита нарушает принципы Privacy by Design и требования законодательства РФ.
2. **Технический долг:** Файловый режим 1С и OLE-интеграции не выдержат 5-кратного роста нагрузки и не поддерживают современные стандарты безопасности.
3. **Организационные ограничения:** Текущий состав IT-отдела (3 человека) критически мал для одновременной поддержки текущей системы и построения новой архитектуры с нуля.

### Рекомендации и план действий

Для минимизации рисков предлагается следующий приоритезированный план мер:

| **Приоритет** | **Направление**      | **Ключевые действия**                                                                                                                                                                |
| ---------------------------- | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Критический       | Безопасность данных | Внедрение движка классификации данных, <br />шифрование (KMS), <br />разграничение доступа (RBAC/ABAC), <br />аудит действий. |
| Высокий               | Архитектура и ПО        | Перевод 1С на Postgres, <br />внедрение API Gateway, <br />постепенная декомпозиция монолита (паттерн Strangler Fig).                             |
| Высокий               | Инфраструктура          | Развёртывание Kubernetes-кластера, <br />настройка резервного копирования и Disaster Recovery.                                                         |
| Высокий               | Персонал                      | Точечный наём DevOps-инженера и Java-разработчика, <br />либо привлечение внешнего подрядчика на этап миграции.            |

## Заключение

Миграция системы «Медикаменте» сопряжена с высокими рисками, преимущественно в области безопасности данных и нехватки ресурсов. 

Успех миграции напрямую зависит от поэтапного подхода (например, Parallel Run или Branch by Abstraction), приоритизации защиты PII-данных на самых ранних этапах и усиления IT-команды. 

Реализация предложенных рекомендаций позволит создать масштабируемую, безопасную и сопровождаемую систему, готовую к 5-кратному росту бизнеса.
